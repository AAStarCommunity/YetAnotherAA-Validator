# DVT pause job (D2)

A separate process on the Mac Mini that pauses every SuperPaymaster operator
that is understaked, by calling SP's permissionless
`pauseUnderstakedOperator(address)`. It replaces the retired guardian watcher's
pause duty (DSR 009967e4). Its scope was approved in DSR 4019916a. It does not
use the SDK attribution API, and the committee keeper is unchanged.

## What one round does

launchd starts `pause-job.mjs` every 600 s. Each start runs one round
(`lib/core.mjs`):

1. **Reconcile (reads only, nothing is broadcast).** Each journalled transaction
   moves through `signed` → `sent` → `included` → `final`:
   - A receipt makes it `included`, and its reservation stays held.
   - It becomes `final` only once its block is at or below `finalized` and is
     canonical. Only then does its full cost move from reserved to spent.
   - The full cost is execution gas plus, on OP, the L1 data fee and operator
     fee. Both fees are read from the chain's own GasPriceOracle at the
     inclusion block; the receipt's own `l1Fee`, when present, is what the chain
     charged and is used instead.
   - A transaction whose block is reorged out goes back to `sent`. Its
     reservation is still held, and the transaction is resent.

   The signer's on-chain nonce must lie between the number of transactions that
   have landed and the journal length. Anything else means someone else used the
   key, and the round stops.

2. **Operator inventory** (`startBlock`, SP's deploy block) **and role
   inventory** (`registryStartBlock`, the Registry's own deploy block, which may
   be earlier). The inventory is built from `OperatorConfigured` logs emitted by
   the **SuperPaymaster proxy**, not by the Registry. A second inventory is
   built from the Registry's `RoleConfigured` logs. Both are read only up to the
   `finalized` block. A cursor moves past a range only after that range's
   `getLogs` succeeds and its logs check out. A failed range raises an alert, is
   retried next round and is never skipped.
3. **One block.** The round pins `B = latest`. Every read and call in the round
   is made at `B`.
4. **Identity check (fail closed).** At `B`, the signer must not be any of the
   following:
   - SP `owner`, `pendingOwner`, `guardian` or `BLS_AGGREGATOR`;
   - Registry `owner`, `pendingOwner` or `blsAggregator`;
   - the owner of any role;
   - a reputation source;
   - a holder of any role.

   The roles checked are the pinned `ROLE_*` set plus every role seen in
   `RoleConfigured`, both the finalized inventory and the not-yet-finalized tail
   up to `B`, which is read in the same round. A configured role that is not in
   the pinned set fails the check. So does any read that fails. When the check
   fails, the round sends nothing.

5. **Decision.** For each operator, the job runs
   `eth_call pauseUnderstakedOperator(op)` from the signer at `B`, then reads
   `operators(op).isPaused` at `B`:
   - the call succeeds and the operator is not paused: a pause candidate;
   - `OperatorMeetsMinimumStake`: fine;
   - `OperatorNotConfigured`: an alert.

   `OperatorPaused` is never decoded: rc.8 changes its fields, and the decision
   uses only the call and the flag. An operator that is understaked and unpaused
   for **2 or more consecutive rounds** raises a **pause timeout** alert.

6. **Send.** `reserve = gasLimit × maxFeePerGas` is held against the cap. The
   signed transaction is written to the state file (fsync) **before** it is
   broadcast. An operator-specific refusal (estimate, gas) moves on to the next
   operator; a chain-wide one (cap, fee ceiling) stops the round. Candidates are
   sent in turn, with at most one transaction in flight. Each must be mined
   within `receiptWaitMs` (default 90 s) before the next is signed. One that is
   not stays in flight, and the next round resends the same bytes. A transaction
   still pending at the start of more than `bumpAfterRounds` rounds (default 3)
   is **replaced at the same nonce** with fees ×1.25, never below the current
   `2 × baseFee + tip`. The extra reservation is checked against the cap first,
   and the new bytes are journalled before broadcast. Every hash signed for that
   nonce is still looked up, and the cost is counted once, from the one that
   mined.

**One provider per round.** The config names two providers, alchemy as primary
and infura as fallback (DSR bd595f0f); their URLs are secret files. A round
probes the primary and uses it throughout. If the probe fails, the whole round
runs on the fallback and an alert names it. A provider that fails mid-round
fails the round and is never swapped out, so the reads at `B` never mix two
providers.

## The SP pin

`sp-pin.json` holds every ABI fragment the job uses and the `ROLE_*` set. All of
it is generated by `gen-sp-pin.mjs` from SP's committed `abis/` and
`IRegistry.sol` at one SP commit, read through the GitHub API with each file's
blob SHA checked. Nothing in it is written by hand. CI runs `--check` to
re-derive it. **Before deploy, regenerate it at the rc.8 tag commit and rerun
`e2e-anvil.mjs` against that commit (DSR 4019916a condition 3).**

## Cap and funding

The cap is **cumulative per chain from funding**: `committed ≤ cap`, where
`committed` is final costs plus every held reservation, an included transaction
counting at the larger of its reservation and its known cost. The job refuses to
send and alerts as soon as the remainder is below `gasLimit × maxFeePerGas`. The
code sets a ceiling per chain, and the config can only lower it:

| chain              | ceiling  |
| ------------------ | -------- |
| Sepolia (11155111) | 0.1 ETH  |
| OP Mainnet (10)    | 0.02 ETH |

**Who funds the signer.** The author picks the source, SP checks it and DSR
gives the go. These sources are never used:

- D `0xb5600060…`;
- the A3a approver and executor;
- any A3a nonce-pinned EOA.

**OP residual (stated, not hidden).** On OP, the sequencer charges the L1 data
fee and the operator fee when a transaction is included. They are not bounded by
the transaction's `maxFeePerGas`, so the cap cannot be an absolute bound there.
The job reserves twice the GasPriceOracle's current fees. Before every broadcast
it re-prices that reservation, which only grows, and it does not rebroadcast
when the cap cannot cover it. A copy already in a mempool can still land. An
overrun can therefore happen only if L1 fees rise past the margin between the
last check and inclusion. If one does, the ledger shows `committed > cap` and
the job stops sending (fail closed) until a new funding. The overrun itself is
recorded: the final cost is written to the journal, not discarded.

**Funding (DSR 65db9e38, N1 ruling).** Fund the signer with exactly the cap, 0.1
ETH on Sepolia and 0.02 ETH on OP, and never top it up without a fresh go from
DSR. That is a process rule. What bounds the job's spending in code is the
**ledger**:

- `committed ≤ cap` (final costs plus held reservations, an included transaction
  at max(reservation, known cost)), under `CAP_CEILING`;
- after any overrun, the job stops sending;
- an included OP cost that cannot yet be read blocks sending until it is read.

`--init` refuses a signer holding **less** than the cap (it would raise a
`deficit` alert every round). It accepts more, with an `inflow` note, because
anyone can send the public address 1 wei before `--init`, and refusing would be
the N1 kill switch at setup time. Our own overfunding is caught earlier: DSR
reads the funding transaction (value equal to the cap, from the approved funder)
before `--init`. The `--init` note goes to stderr only; the first round's
funding check raises the same `inflow` through the normal alert path.

A balance above what the ledger explains (`cap - spent - included costs`) raises
an **`inflow`** alert, and **sending continues**. It is never a halt. A halt
would let anyone switch the keeper off with 1 wei of dust, and the first to want
that is the operator about to be paused (clestons #432 N1). Extra balance never
raises the ledger's bound. A balance **below** what the ledger explains, even
allowing for every held reservation (`cap - committed`), raises a **`deficit`**
alert (the ledger may undercount a cost, e.g. a receipt `l1Fee` of 0). It is
also an alert only. Because it allows for every hold, an undercount shows only
once its reservation is released; that looseness is the price of never alerting
on a pending or re-included transaction.

A new cap is a new funding: start a new ledger (a new state) for it. Do not edit
`cap`, which the job refuses.

## Install on the Mini

1. Create the signer with `node deploy/pause-job/new-signer.mjs`. It makes a
   fresh key at nonce 0 and writes an encrypted keystore. The password is a
   random 0600 file, and the script prints only the address. Never import a key:
   never 0xB747, never any privileged identity.
2. Create the secrets in `~/.aoa-pause-job/secrets`, a 0700 directory with one
   0600 file per secret. No value goes through argv or shell history:

   ```zsh
   read -rs "v?value: "; install -m 600 /dev/null "$DIR/aoa-dvt-pause-rpc"; printf '%s' "$v" > "$DIR/aoa-dvt-pause-rpc"
   ```

   The secrets are:
   - `aoa-dvt-pause-rpc-primary` (the alchemy URL);
   - `aoa-dvt-pause-rpc-fallback` (the infura URL);
   - `aoa-dvt-alert-bot-token` (the existing aastar-monitor bot, DSR bd595f0f).

   `new-signer.mjs` creates `aoa-dvt-pause-keystore-pw`.

3. Write `~/.aoa-pause-job/config.json` from `config.example.json`. `startBlock`
   is SP's deploy block, and the addresses come from the manifest.
4. Fund the signer as described under "Cap and funding".
5. Run `node deploy/pause-job/pause-job.mjs --config … --init`. It refuses if
   the signer's nonce is not 0 or if a state already exists.
6. Install `io.aastar.dvt-pause-job.plist`: render it,
   `launchctl bootstrap gui/$(id -u) …`, and check that `launchctl print` shows
   `run interval = 600`.
7. Run `node deploy/pause-job/preflight.mjs`. It must print no FAIL.

**One instance.** The lock is a listening socket on `127.0.0.1:lockPort`. The
kernel releases it when the process dies, so there is no stale lock file to take
over.

## Preflight (DSR 502ccd64)

> **rc.8 status:** this job is retired and never deployed (DSR fae09c1e): its
> signer was refunded and deleted. Its code stays: the pause detector
> (`deploy/pause-detector`) reuses its read path, its secret-file reader
> (`lib/secret-file.mjs`) and its SP pin. Preflight below now checks
> launchd-**on** for the detector and the keeper, plus the detector's last
> status.

**What preflight is, and what it is not (clestons #432 L4).** Preflight guards
against operator mistakes, such as a forgotten keeper still loaded or an armed
node container. It is not a security boundary. Anything running as this account
could defeat it, for example with a wrapper that builds its path at run time, a
binary that sends transactions, or a job installed after the check ran. The
boundary is elsewhere:

- a signer that holds no role;
- the funding cap;
- the on-chain identity check that runs every round.

`preflight.mjs` covers the three Phase D items that live on DVT's own host.
Until this PR merged, they were manual items on the launch checklist.

- **launchd-on** (rc.8: the D2 job is retired, DSR fae09c1e; pausing is "detect,
  then act by hand" with `deploy/pause-detector`):
  - the committee keeper is not loaded;
  - apply-rotation is not loaded;
  - this D2 pause job (`io.aastar.dvt-pause-job`) is **not** loaded;
  - the read-only pause detector (`io.aastar.dvt-pause-detector`) **is** loaded,
    and so is the price keeper (`io.aastar.price-keeper`, the one approved
    sender, not scanned);
  - no other loaded job runs a DVT transaction-sending script. This is judged by
    the job's ProgramArguments, not its label: a script name anywhere in an
    argument counts, and shell wrapper scripts are read. A wrapper that cannot
    be read fails. The plists in `~/Library/LaunchAgents` are read as well.
  - Wrapper scripts are followed transitively, up to 4 levels, from absolute
    paths and from paths relative to the job's working directory or to the
    referring script. Whole-line comments are ignored. A chain deeper than that
    is reported as not followed (FAIL), never certified clean. Paths built at
    run time (`$VAR`) cannot be followed; that is a stated residual.
  - The only exceptions are in `preflight-reviewed.json` (DSR bc3be95b). An
    entry passes only when all of the following hold:
    - the label matches exactly;
    - a plist for it exists in `~/Library/LaunchAgents`;
    - the plist's **full** ProgramArguments are exactly
      `[interpreter, <repo>/<wrapper>, ...args]`;
    - the arguments launchd actually loaded equal the plist's;
    - the environment launchd actually loaded has the same variable names (apart
      from the two that launchd adds), and no shell start-up variable
      (`BASH_ENV`, `ENV`, `BASH_FUNC_*`) is present, whether set or inherited;
    - the plist's environment variable names are exactly the listed ones;
    - every file the mode runs hashes to its pinned sha256, hashed at the paths
      the plist resolves.

    Today the one entry is `io.aastar.dvt-committee-health`, which runs
    `local-heartbeat.sh health` and, through it, `committee-health.mjs`; it
    sends nothing. The same wrapper's `apply` mode broadcasts, and that mode is
    not covered. A forbidden label can never be an exception.

    The file changes only through a PR whose body states the new hashes. CI
    checks the hashes against the repository's files.
- **node-slash-off**: the node inventory must not be empty, and every running
  `dvt-node-*` container must be in it. On every DVT node container,
  `AUDIT_ENABLED` and `AUDIT_EXECUTE_SLASH` are absent or exactly `"false"`.
- **spParity**: always **MANUAL** until SP's DVTValidator-0.8.0 is on SP main
  (DSR 48be82a3).

## Tests

- `npm run check:pause-job`: the pure cells (state invariants, config, pin
  parser, preflight rules).
- `node deploy/pause-job/e2e-anvil.mjs --sp <SP checkout at sp-pin.json's commit>`:
  the pause path end to end against SP's real compiled contracts, deployed by
  SP's own `DeployAnvil.s.sol`. It covers the pause, no-op on already paused,
  the identity check, the cap, crash recovery, a foreign nonce, a failed
  `getLogs` range and the pause timeout.
