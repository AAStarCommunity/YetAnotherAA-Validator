# DVT pause job (D2)

A separate process on the Mac Mini that pauses every SuperPaymaster operator
that is understaked, by calling SP's permissionless
`pauseUnderstakedOperator(address)`. It replaces the retired guardian watcher's
pause duty (DSR 009967e4). Its scope was approved in DSR 4019916a. It does not
use the SDK attribution API, and the committee keeper is unchanged.

## What one round does

launchd starts `pause-job.mjs` every 600 s. Each start runs one round
(`lib/core.mjs`):

1. **Settle.** At most one transaction is in flight. If its receipt is missing,
   the job resends the same signed bytes. The signer's on-chain nonce must be
   between the journal's mined count and that count plus the in-flight
   transaction. Anything else means someone else used the key, and the round
   stops.
2. **Operator inventory.** The inventory is built from `OperatorConfigured` logs
   emitted by the **SuperPaymaster proxy**, not by the Registry. A second
   inventory is built from the Registry's `RoleConfigured` logs. Both are read
   only up to the `finalized` block. A cursor moves past a range only after that
   range's `getLogs` succeeds and its logs check out. A failed range raises an
   alert, is retried next round and is never skipped.
3. **One block.** The round pins `B = latest`. Every read and call in the round
   is made at `B`.
4. **Identity check (fail closed).** At `B`, the signer must not be any of the
   following:
   - SP `owner`, `pendingOwner`, `guardian` or `BLS_AGGREGATOR`;
   - Registry `owner`, `pendingOwner` or `blsAggregator`;
   - the owner of any role;
   - a reputation source;
   - a holder of any role.

   The roles checked are the pinned `ROLE_*` set plus every role seen in
   `RoleConfigured`, both the finalized inventory and the not-yet-finalized tail
   up to `B`, which is read in the same round. A configured role that is not in
   the pinned set fails the check. So does any read that fails. When the check
   fails, the round sends nothing.

5. **Decision.** For each operator, the job runs
   `eth_call pauseUnderstakedOperator(op)` from the signer at `B`, then reads
   `operators(op).isPaused` at `B`:
   - the call succeeds and the operator is not paused: a pause candidate;
   - `OperatorMeetsMinimumStake`: fine;
   - `OperatorNotConfigured`: an alert.

   `OperatorPaused` is never decoded: rc.8 changes its fields, and the decision
   uses only the call and the flag. An operator that is understaked and unpaused
   for **2 or more consecutive rounds** raises a **pause timeout** alert.

6. **Send.** `reserve = gasLimit × maxFeePerGas` is held against the cap. The
   signed transaction is written to the state file (fsync) **before** it is
   broadcast. Candidates are sent in turn, with at most one transaction in
   flight. Each must be mined within `receiptWaitMs` (default 90 s) before the
   next is signed. One that is not stays in flight, and the next round resends
   the same bytes. A transaction still pending at the start of more than
   `bumpAfterRounds` rounds (default 3) is **replaced at the same nonce** with
   fees ×1.25, never below the current `2 × baseFee + tip`. The extra
   reservation is checked against the cap first, and the new bytes are
   journalled before broadcast. Every hash signed for that nonce is still looked
   up, and the cost is counted once, from the one that mined.

**One provider per round.** The config names two providers, alchemy as primary
and infura as fallback (DSR bd595f0f); their URLs are secret files. A round
probes the primary and uses it throughout. If the probe fails, the whole round
runs on the fallback and an alert names it. A provider that fails mid-round
fails the round and is never swapped out, so the reads at `B` never mix two
providers.

## The SP pin

`sp-pin.json` holds every ABI fragment the job uses and the `ROLE_*` set. All of
it is generated by `gen-sp-pin.mjs` from SP's committed `abis/` and
`IRegistry.sol` at one SP commit, read through the GitHub API with each file's
blob SHA checked. Nothing in it is written by hand. CI runs `--check` to
re-derive it. **Before deploy, regenerate it at the rc.8 tag commit and rerun
`e2e-anvil.mjs` against that commit (DSR 4019916a condition 3).**

## Cap and funding

The cap is **cumulative per chain from funding**: `spent + reserved ≤ cap`. The
job refuses to send and alerts as soon as the remainder is below
`gasLimit × maxFeePerGas`. The code sets a ceiling per chain, and the config can
only lower it:

| chain              | ceiling  |
| ------------------ | -------- |
| Sepolia (11155111) | 0.1 ETH  |
| OP Mainnet (10)    | 0.02 ETH |

**Who funds the signer.** The author picks the source, SP checks it and DSR
gives the go. These sources are never used:

- D `0xb5600060…`;
- the A3a approver and executor;
- any A3a nonce-pinned EOA.

A new cap is a new funding: start a new ledger (a new state) for it. Do not edit
`cap`, which the job refuses.

## Install on the Mini

1. Create the signer with `node deploy/pause-job/new-signer.mjs`. It makes a
   fresh key at nonce 0 and writes an encrypted keystore. The password is a
   random 0600 file, and the script prints only the address. Never import a key:
   never 0xB747, never any privileged identity.
2. Create the secrets in `~/.aoa-pause-job/secrets`, a 0700 directory with one
   0600 file per secret. No value goes through argv or shell history:

   ```zsh
   read -rs "v?value: "; install -m 600 /dev/null "$DIR/aoa-dvt-pause-rpc"; printf '%s' "$v" > "$DIR/aoa-dvt-pause-rpc"
   ```

   The secrets are:
   - `aoa-dvt-pause-rpc-primary` (the alchemy URL);
   - `aoa-dvt-pause-rpc-fallback` (the infura URL);
   - `aoa-dvt-alert-bot-token` (the existing aastar-monitor bot, DSR bd595f0f).

   `new-signer.mjs` creates `aoa-dvt-pause-keystore-pw`.

3. Write `~/.aoa-pause-job/config.json` from `config.example.json`. `startBlock`
   is SP's deploy block, and the addresses come from the manifest.
4. Fund the signer as described under "Cap and funding".
5. Run `node deploy/pause-job/pause-job.mjs --config … --init`. It refuses if
   the signer's nonce is not 0 or if a state already exists.
6. Install `io.aastar.dvt-pause-job.plist`: render it,
   `launchctl bootstrap gui/$(id -u) …`, and check that `launchctl print` shows
   `run interval = 600`.
7. Run `node deploy/pause-job/preflight.mjs`. It must print no FAIL.

## Preflight (DSR 502ccd64)

`preflight.mjs` covers the three Phase D items that live on DVT's own host.
Until this PR merged, they were manual items on the launch checklist.

- **launchd-off**:
  - the committee keeper is not loaded;
  - apply-rotation is not loaded;
  - the pause job **is** loaded;
  - no other loaded job runs a DVT transaction-sending script. This is judged by
    the job's ProgramArguments, not its label.
- **node-slash-off**: on every DVT node container, `AUDIT_ENABLED` and
  `AUDIT_EXECUTE_SLASH` are absent or exactly `"false"`.
- **spParity**: always **MANUAL** until SP's DVTValidator-0.8.0 is on SP main
  (DSR 48be82a3).

## Tests

- `npm run check:pause-job`: the pure cells (state invariants, config, pin
  parser, preflight rules).
- `node deploy/pause-job/e2e-anvil.mjs --sp <SP checkout at sp-pin.json's commit>`:
  the pause path end to end against SP's real compiled contracts, deployed by
  SP's own `DeployAnvil.s.sol`. It covers the pause, no-op on already paused,
  the identity check, the cap, crash recovery, a foreign nonce, a failed
  `getLogs` range and the pause timeout.
