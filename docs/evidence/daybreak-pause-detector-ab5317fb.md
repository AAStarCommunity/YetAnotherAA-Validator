## Framework (DSR, 2026-11-17)

Each High is put into one of three classes:

- **(i)** a real problem with a small, definite fix;
- **(ii)** a trade-off that is disclosed and that DSR has already accepted;
- **(iii)** not a real problem, with the code that shows it.

Daybreak's severity is not adopted as given. It is re-rated by consequence. This
detector is read-only and holds no signing key, so its worst outcome is that an
understaked operator is missed or alerted late. The paper already states that
pause latency is bound by human response.

Budget: one round of verification (this one), one round of fixes, then one more
Daybreak run on the fixed head. Any High still reported after that is ruled on
by DSR one by one: disclose it, or defer the deployment.

**This file is the verification only. Nothing has been fixed yet, by DSR's
instruction.**
