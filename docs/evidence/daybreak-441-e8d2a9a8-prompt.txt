What this is (verify against the code; do not take it on trust):
- SP BLSAggregator-4.14 stores, per proposal, signersCommitment = keccak256(abi.encode(domainSeparator(), TAG_SIGNERS_COMMITMENT, key, messageHash, signerMask, signers, blockhash(block.number - 1))). Review strictly and adversarially. In particular:
1. False accept: any proof the verifier accepts although the named guardians did not sign what the stored commitment records (encoding ambiguity, signer order/duplicates, mask vs signer list, another proposal's or another key's commitment, cross-aggregator/chain replay, the parentBlockHash binding).
2. False reject: an honest proof refused (wrong key choice, wrong parent block, version gating).
3. Deploy script gates (Gate A', EXPECTED_AGGREGATOR_VERSION, canonical aggregator) that can be bypassed or misconfigured into deploying against the wrong aggregator.
4. Off-chain: the watcher reading parentBlockHash from the wrong block, failing open when it cannot read, or an encoder/Solidity layout mismatch (goldens on both sides).
5. The drill or E3 producing anything usable as a real slash on a live chain (a signature, a filled proof against real guardians), key handling, injection in the .sh.
6. Acceptance checks that pass vacuously.
